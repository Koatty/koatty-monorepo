# Koatty 4.3.0 迁移指南（安全加固）

> 发布：`koatty@4.3.0`（全部受影响包 minor 升级）
> 关联：[`koatty-hardening-and-ai-evolution-plan.md`](../koatty-hardening-and-ai-evolution-plan.md) Phase B · ADR-101/102/103
> 本版本把"失败即放行"（fail-open）的默认值全部改为"失败即拒绝"（fail-closed）。**所有行为变更均提供回退开关**；明确缺陷类修复（`escapeHtml`、插件重复执行、RedLock 重置、Redis 端口）不提供回退。

## 一键回退

`config/security.ts` 中设置：

```ts
export default {
  legacyDefaults: true,   // 恢复 4.2.x 的全部宽松默认值（5.0.0 移除）
};
```

启用后启动日志会以 `WARN` 逐条列出被回退的项，便于运维发现遗留配置。也可以按字段单独覆盖（见下文各节）。

## 行为变更清单

### 1. 请求体解析失败返回 400/413/415（SEC-02）

畸形 JSON/表单/XML 请求体现在返回 **400**；超过大小限制返回 **413**；不支持的 Content-Encoding 返回 **415**。原来"畸形请求体静默得到 `{}`"的行为不再成立。错误消息不包含请求体片段。

```ts
// config/security.ts
export default {
  payload: { onParseError: 'empty' },   // 恢复旧 behavior
};
```

### 2. 请求体上限 1mb（生产环境）

请求体大小限制改由安全画像决定：`strict`（生产默认）**1mb**、`standard` **5mb**、`development` **20mb**。大请求体被拒绝并返回 413。同时，框架内置的 `config/router.ts` 默认值不再携带 `limit: '20mb'`——**如果你的项目 `config/router.ts` 显式设置了 `payload.limit`，它仍然优先生效**；未设置则跟随画像。

```ts
// config/security.ts
export default {
  payload: { limit: '20mb' },   // 恢复旧行为
};
// 或在 config/router.ts 中保留 payload.limit: '20mb'（显式配置优先）
```

### 3. DTO 校验白名单（SEC-03）

DTO 未声明的字段默认被**剥离**（`whitelist: true`）；`strict` 画像下多余字段直接拒绝（`forbidNonWhitelisted`），返回 400。`__proto__`/`constructor`/`prototype` 键永远不进入 DTO 实例。

- 在 DTO 上补声明你实际需要的字段（加校验装饰器或 `@Allow()`）；
- 或 `config/security.ts`：`validation: { whitelist: false }` / `{ whitelist: true, forbidNonWhitelisted: false }`。

注意：class-validator 的白名单以"带校验装饰器（或 `@Allow()`）的字段"为准，不带任何装饰器的属性也会被剥离。

### 4. AOP 切面异常向上抛出（SEC-01）

`@Before`/`@After`/`@Around`（含 Each 系列）切面抛错时，默认**中断业务方法**并向上传播异常。After/AfterEach 切面可通过 `options.result` 拿到业务方法返回值。

```ts
// 对确实可以失败的切面（如纯日志）单独豁免：
@Before(AuditAspect, { onError: 'log' })
// 或全局回退（config/security.ts）：
export default { aop: { onAspectError: 'log' } };
```

### 5. GraphQL 安全默认值（SEC-04）

- GraphiQL playground：生产环境**关闭**（原代码实际默认开启）；
- `introspection: false` 现在真正生效（内置 `NoSchemaIntrospectionCustomRule`）；
- 深度限制为**内置实现**（不再依赖 `graphql-depth-limit`，可从依赖中移除）；
- 复杂度限制仍依赖可选包 `graphql-query-complexity`（已声明为 optional peer）——**配置了 `complexityLimit` 但未安装该包时启动失败**（原来静默跳过）；
- GraphiQL 页面不再从 unpkg 加载脚本。

回退：`config/security.ts` → `graphql: { playground: true, introspection: true, depthLimit: 0, complexityLimit: 0 }`。

### 6. 上传限制与临时文件（SEC-05）

- `maxFiles` 默认 10（strict），超出返回 413；`maxFields`/`maxFieldsSize` 同样画像化；
- `keepExtensions` 默认 **false**（不再保留攻击者可控的文件名扩展名）；
- `multiples: true` 时数组形态的临时文件也会被清理（原来泄漏）；
- 上传临时目录默认 `os.tmpdir()/koatty-upload-<pid>`；
- 新增 `safeFilename()` 导出：`originalFilename` 不可信，保存文件前必须经过它。

### 7. `/metrics` 与健康检查（SEC-06）

- `/health`、`/healthz` 只返回 `{"status":"ok"}`（存活探针），不再包含内存/CPU 等；
- `/ready` 停机期间返回 503；
- `/metrics` 按 `ops.exposeMetrics` 策略：`off`（404）/ `internal`（默认，仅 loopback/RFC1918/allowCidrs 或 Bearer token）/ `public`；
- Prometheus 指标端口默认绑定 **127.0.0.1**；
- 详细健康信息需要 token（`config/ops.ts` 的 `token`/`allowCidrs`）。

回退：`config/security.ts` → `ops: { exposeMetrics: 'public' }`。

### 8. WebSocket 默认加固（SEC-08）

- `maxPayload` 画像化（strict 1 MiB，原 ws 库默认 100 MiB）；
- `perMessageDeflate` 默认关闭；
- 升级请求校验 `Origin`（`ws.checkOrigin` 画像开关 + `config/ws.ts` 的 `allowedOrigins`，支持 `*.example.com` 通配）→ 不匹配返回 403；**生产开启 checkOrigin 后必须配置 allowedOrigins，否则所有升级被拒**（启动时有 WARN）；
- 错误回传只含 `{ error, requestId }`，不再回显 `error.message`；
- 连接数上限（`ws.maxConnections`）超限返回 503。

回退：`config/security.ts` → `ws: { checkOrigin: false, maxPayload: 0 }`。

### 9. 请求 ID 校验（SEC-07/15）

外部 `X-Request-Id` 必须匹配 `^[A-Za-z0-9._:-]{1,128}$`，否则丢弃并生成新 ID（原值不入日志）。**不再从 query 读取请求 ID**（`requestIdFromQuery: true` 可恢复）。拓扑记录的 `service` 请求头默认不信任（`opentelemetryConf.trustServiceHeader: true` 开启）。访问日志改为结构化对象输出。

### 10. TypeORM 生产日志（SEC-11）

`NODE_ENV=production` 下默认 `logging: ['error']`（原来全部 SQL 与参数入日志）；SQL 参数中的敏感键（password/token/...）输出前脱敏。显式设置 `logging` 不受影响。

### 11. Swagger 生产默认关闭（SEC-14）

`NODE_ENV=production` 下默认不挂载；显式 `enabled: true` 会输出 WARN。开发环境默认开启。

### 12. TLS 最低版本（SEC-12）

HTTPS/WSS 默认 `minVersion: 'TLSv1.2'`；TLSv1.0/1.1 连接被拒绝（连接池安全评分也不再给 TLSv1.1 加分）。显式 `ssl.minVersion: 'TLSv1.3'` 可收紧。

## 无回退的缺陷修复

- `escapeHtml`：`&` 被转义、`"` 产出合法的 `&quot;`（原来产出非法实体 `&quote;`）；`unescapeHtml`（原 `escapeSpecial`）按序还原。若前端依赖旧的错误输出需调整。
- `isNumberString` 重写为无回溯正则（修复 ReDoS），历史宽松语义（如 `'1e'`）保留。
- 插件仅有 `run()` 时**只执行一次**（原来 appReady + load 阶段各一次）。需要加载期执行的插件请显式 `@OnEvent(AppEvent.loadComponent)`。
- 启动失败会向上抛出/退出（原来只记日志继续运行）。
- Redis 默认端口 `3306` → `6379`（未显式配置端口且依赖旧错误值的场景才受影响）。
- gRPC `ListServices` 能正确列出服务（原来恒为空）。
- `koatty_cli` 的 bin 修复（原 ESM/CJS 不匹配导致安装后直接崩溃）。
- `koatty apply` 默认 dry-run 预览，`--yes` 才真正写入；所有写入限制在项目根目录内（SEC-10）。
